# 首次真实模型 A/B/C 对照结果（2026-10-10，6 任务）

## 运行配置（可复现台账）

- **模型**：session-agent（GLM 会话模型，经 OpenAI 兼容桥 `scripts/agent_api_shim.py` 接入，
  三组同一模型；token 用量为估算值）。
- **judge**：session-agent（与被测同一模型——**自评 judge 偏差风险已知**，见下）。
- **预算**：max_steps=6、max_tool_calls=8、时限 60s/工具调用；三组共用。
- **沙箱**：env 白名单 + RLIMIT + 网络隔离（user+net namespace，本机可用）。
- **任务**：real/train 前 6 个（确定性选择）；其中 2 个任务的官方数据集为 Stata .dta
  格式，当前适配器只支持 CSV → 这 2 个任务所有组均无可评答案（同等受限）。
- 原始记录：`raw/`（每任务每组的 answer/trace/cost 与评分明细）。

## 如实结论：本样本未观察到 Copilot 模块的收益

按评测协议的诚实原则，收益为零也要如实报告并归因。归因分析：

1. **答案趋同（主因）**：session-agent 具备足够的工具使用能力，三组都通过同一次
   沙箱相关分析得到相同的结论——注入的诊断观测没有提供模型自己算不出来的信息。
   在"单表+强工具模型"的场景下，B（画像）与 C（画像+观测）无差异。
2. **观测噪声挤占（真实缺陷，已定位）**：宽表任务中 `metric_direction_unresolved`
   等噪声观测把 C 组上下文里最有用的 `relation_map`/`group_comparison` 挤出了
   9000 字符截断窗口（本轮评测冻结未修代码；修复方向：按信息量排序观测、合并
   方向未声明提示、优先保留关系图与组间比较）。
3. **样本与统计功效**：n=6（2 个不可评），CI 宽达 [-0.01, 0.70]，无法区分小差异。

## 过程中发现的真实问题（下一轮修复清单）

1. **金标与数据分歧**：任务 3 金标称 BEL_evol 与物种形成率"无显著关联"，但全数据
   Pearson r=0.421——金标可能基于不同模型设定（如系统发育校正）。评测答案因此被
   判 0 分。启示：对数据驱动结论，答案与金标冲突时应输出"数据-金标分歧"标记而非
   直接采信任何一方。
2. **.dta 支持**：2/6 任务因此不可评；正式 20-30 任务评测前必须支持（或剔除该类
   任务并注明）。
3. **观测打包策略**：见上，需按信息量优先级重排。
4. **自评 judge 偏差**：judge 与被测为同一模型；正式报告需要换独立 judge 或官方
   脚本复核（本轮成绩仅作可信性验证，不与论文数字比较）。

## 结论定位

本结果**验证的是评测管道的真实可用性**（真实模型、真实沙箱、官方协议评分、成本
差值计量、not_evaluable 分离报告全部按设计工作），**不构成**"Copilot 优于/不优于
普通 LLM"的结论——样本太小且答案趋同。下一步（按既定路线）：修复上述 4 项 →
扩展到 20-30 任务重跑 → 若 C 仍无收益，按失败样本归因诊断模块的价值边界。
