# 第四轮：首次跨模型独立对照（2026-10-11，DeepSeek-flash 被测 × 12 新鲜任务）

## 里程碑

- **被测模型 = deepseek-flash（独立第三方，用户自备 API），judge = session-agent**
  ——评审与被测**模型分离**，四轮审查要求的最后一块达成；agent 阶段由被测
  直连 API 实时响应（无桥、无预写），judge 经桥盲评（无组别标签）。
- 12 新鲜任务（10 数据集族，排除此前全部 32 个已用任务）。
- 沙箱为本轮新接入的 **bwrap 容器级隔离**（实测越权读取宿主文件被阻断）。

## 三个发现

1. **B 组完成率崩塌（17%）是本轮最重要信号**：预注入画像上下文使 deepseek-flash
   的有效答案率暴跌（A 42% → B 17%）——长上下文/复杂列名干扰了小模型的输出
   格式（DSML agent 格式 + JSON 协议冲突也有关，见下）。**这直接回答了审查的
   问题："额外诊断信息在什么情况下会干扰模型"——对小模型，预先注入的长上下文
   本身就是干扰源。**
2. **精度方向上 C ≥ A**（C2 0.575 > A 0.571 > C1 0.500；C1_vs_A +0.25），
   但可评配对仅 1–2 个，统计上不可分辨——只能作为下一轮扩样的方向性信号。
3. **第三方模型接入暴露真实兼容性缺口**：deepseek-flash 以自有 DSML agent
   格式输出工具调用（`<｜｜DSML｜｜ invoke>`），首轮 83% 组次因解析失败作废；
   修复解析器兼容后重跑。这说明评测协议需要**模型适配层**——已实现 DSML，
   其他模型的 agent 格式将同样按需补充。

## 证据指标（诚实）

verified_rate 仅 2.5–4.9%（deepseek 的断言多为自定义形式：PCA 分数/分组
差值等，验证器尚不支持）；unverifiable 92–100%。与 session-agent 轮的
0.93 一致地暴露：**验证器覆盖是当前最大短板**——扩展断言形式支持是下一步。

## 已知局限

- 可评任务少（B 组仅 1 个）：n 太小，任何组间比较都不具统计效力；
- judge = session-agent 与系统开发者同源（模型不同但开发链路相同）；
- deepseek-flash 为推理型小模型，其 DSML 行为与 max_steps 预算的交互
  未调优（预算对所有组一致，公平性不受影响）；
- 污染注记：test 划分金标公开。

## 下一步

1. 验证器扩展（PCA/分组均值断言）+ 断言形式引导（prompt 鼓励可验证断言）；
2. B 组崩塌机制分析（读轨迹：DSML 格式 vs 上下文长度的交互）；
3. 扩样到 20–30 任务重跑（待 deepseek 额度/用户确认成本 ≈ 100–150 万 tokens）。
