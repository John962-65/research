# 第三轮：现场协议首次真实对照（2026-10-11，12 新鲜任务 × A/B/C1/C2）

## 本轮落实的审查要求

1. **取消预生成应答**（审查最高优先级）：被测模型对 48 个组次请求**实时**响应——
   每组接收各自实际上下文、独立决定是否调用工具（本轮 agent 阶段共发起 44 次
   python/diagnose 调用，代码逐次写在响应里）、实时作答；agent 阶段未读取任何
   金标；旧 prepared 文件在启动前已删除。
2. **任务新鲜度**：12 个任务全部来自 test 划分、且排除前两轮用过的 6 个——
   会话模型此前从未分析过这些数据集；按数据集轮转选取（10 个数据集族）。
3. **盲评**：judge 上下文不含组别/被测标签；var 维度附确定性启发式交叉核对。
4. **证据三指标** + ols_beta 验证器 + 数据集聚类 CI + C2 按需诊断消融全部启用。

## 三个真实发现

1. **精度维度：四组无可测差异**。实时协议下答案不再逐字相同（轨迹可见真实行为
   分化），但在这些任务上结论趋同——单表分析的最优路径唯一，上下文差异未改变
   科学结论。
2. **成本维度：第一个可测量的 Copilot 收益**——C1 的预注入观测使部分任务免工具
   往返，LLM 调用 32（A）→ 21（C1），**省 34%**；C2 的按需诊断比 C1 多 5 次调用
   且在 2/12 任务上返回无关观测（时代分组的虚假比较、宽表年份自相关）——按需
   策略的开销首次被量化。
3. **证据三指标诚实暴露验证缺口**：unverifiable_rate = 1.0（20 条断言全部无法
   复算）。原因：任务 9 的 ols_beta 断言因 BA 布尔列（'True'/'False' 字符串）
   在 regress 中转 float 失败而不可解——**验证器缺陷**（需布尔/分类编码支持），
   已列入下一轮修复；其余断言为非列均值类型。unverifiable=1.0 如实呈现，
   不再被"无依据比例 0%"掩盖。

## 准确率绝对值说明

0.42（本轮）低于第二轮的 0.68：任务更难（PCA 主成分、面板因果、问卷列语义
缺失）且无预写答案。4 个任务上 agent 如实报告"不可分析/不可复算"（数据列
结构不支持金标所问），这类诚实受限反映在 rel=C 上。

## 已知局限（不因本轮结果改变）

- 被测模型与 judge 仍为同一会话模型（residual bias）；
- 沙箱文件系统未隔离（容器运行时已探测可用、未接入）；
- 污染注记：任务来自公开 answer key 的 test 划分；
- 结果仅描述本 12 任务子集，不外推。

## 下一步（按价值排序）

1. 修 regress 的布尔/分类编码 → 重验 ols_beta 断言（降低 unverifiable）；
2. 容器沙箱接入（bwrap 已探测可用）；
3. 用独立第三方被测模型复跑同协议（需提供端点）——同源偏差消除后，
   成本收益（C1 省 34% 调用）是否伴随精度变化才能真正定论。
