# 第二轮真实对照（2026-10-11，20 任务，修复后重跑）

## 本轮前提（第一轮 FINDINGS 的 4 项修复全部落地）

1. 观测打包：方向噪声合并 + 按信息量优先级排序 + 超预算从尾部丢弃（C 组关系图不再被挤出）；
2. .dta 支持（pandas [eval] extra）：immigration 两任务从"不可评"变为完全可评；
3. 金标-数据分歧诊断：每任务一次 judge 诊断，divergence=true 的任务分数解读为分歧而非模型错误；
4. 自动应答器：会话模型预写全部答案/判定（基于真实数据分析），机械分发 380 个请求，零 miss。

- **分歧诊断标记 4 个任务**：evolution m1/m2、immigration m0/m1——全部是"金标基于

- C_vs_A / C_vs_B = 0.0：三组答案完全趋同。

## 如实归因

1. **分析质量本身很高**：16/20 任务与金标方向/形式/系数一致（nls 系列多个系数
   精确命中：0.3596、1.5799、1.1840、0.5256/0.4715；考古 5 题世纪定位一致）。
2. **三组同分的根本原因是同源偏差**：三组被测都是同一个会话模型，对同族任务
   采取同一最优分析路径（一次 OLS/世纪聚合即可解决），注入的画像/观测不改变
   行为。**这不是"Copilot 无用"的证据，而是"同一模型自评无法检测模块增益"的
   证据**——收益验证必须用独立第三方模型跑 A/B/C。
3. **分歧诊断价值得到验证**：4 个任务的低分被自动归因为金标-数据方法分歧，
   而非模型错误——这正是第一轮任务 3 "莫名 0 分"的解答。
4. 残留 bug（当场修复）：runner 的数值断言重算曾用 csv-only 加载器，把 .dta
   任务误标 not_evaluable（不影响分数，影响该计数口径）。

## 结论定位与下一步

- 本轮验证：官方协议评分、分歧诊断、观测打包、.dta 支持在 20 任务真实运行中
  全部按设计工作；**成绩不可与论文数字比较**（judge=被测、dev 集含 test 任务污染注记）。
- **下一轮核心：接入独立第三方 LLM 作为被测模型复跑 A/B/C**（需提供可用端点），
  三组行为分化后才可能观察到 Copilot 模块的真实增益/代价；同时可考虑 judge
  与被测分离。
