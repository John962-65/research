# T19：真实用户试用工具包（状态：not_measured）

复核版本：v1.1（T19）。**真实参与者是否发生：否**（participants=0、
pairs=0）。本文件是采集入口与材料准备；没有真实参与者数据之前，
任何效率/正确率描述都保持 `not_measured`，不得生成比例。

## 1. 材料集（预先冻结标签）

- 结构化规则案例：`examples/review-evaluation-cases.json`（12 例，含
  正确比较、无效比较、证据不足、合格负结果与覆盖反例；期望决定由真实
  决策函数复核——见 `tests/test_review_evaluation.py`）。
- 每例的"预先冻结标签"即 `expected` 字段；争议案例在试用前由具备相关
  经验的标注者仲裁，仲裁结果回写该文件并留注释。

## 2. 参与者与配对流程

1. 招募 3–5 名有相关背景的参与者；每人分配匿名 `participant_id`。
2. 每个任务对（`pair_id`）包含同一案例的两种条件：`manual`（普通 AI
   对话辅助）与 `assisted`（本系统）；同一参与者的两条件材料相同，
   案例顺序在参与者间交错（拉丁方），避免记忆答案。
3. 两种条件的可用模型、时间上限与工具在试用前书面固定并记录。

## 3. 采集格式

`examples/review-session-template.csv`：
`participant_id,pair_id,condition,case_id,seconds,decision`

- 导入器已强制：每对必须同时含两种条件、拒绝重复/未知案例/非法时间
  （`tests/test_review_evaluation.py` 覆盖）。
- 额外建议记录列（可追加，不破坏既有导入）：人工操作秒数（与总耗时
  分开计）、纠正次数、等待/失败时间、备注。
- 所有超时、失败、人工纠正与等待时间必须如实记录；实际未发生的调用
  或未完成的任务不得补造。

## 4. 分析与报告口径

- 指标定义与统计口径见任务书 T11 表（端到端耗时、人工操作时间、
  错误放行率、错误阻断率、决策正确率、资源成本、使用障碍）。
- 缺少某类样本 → 该比例显示 `not_measured`，不显示 0%。
- 报告只做描述性统计；不声称普遍收益。
- 采集完成后：`research-agent` 评测入口（`review_evaluation`）导入 CSV
  生成可复算汇总，原始 CSV 与汇总一起匿名归档。
